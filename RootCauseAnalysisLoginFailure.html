🛡️ The 4 Fundamental Architectural & Security Barriers
1. macOS TCC Sandbox Blocks Keystroke Synthesis
OS SECURITY
When Antigravity attempted to execute AppleScript via osascript to automatically type the username and password into the open Trader Workstation dialog, macOS blocked the action at the kernel level.

Under Apple's Transparency, Consent, and Control (TCC) framework, background processes and terminals are strictly prohibited from generating simulated keyboard/mouse events into password fields without explicit OS Accessibility permissions.
$ osascript -e 'tell application "System Events" to keystroke "password"'
➔ 204:236: execution error: System Events got an error: osascript is not allowed to send keystrokes. (1002)
2. IBKR Decoupled Socket Architecture
BROKER DESIGN
Unlike modern cloud brokers (e.g., Alpaca, Binance) that accept static API Key + Secret headers directly over public HTTPS, Interactive Brokers enforces a decoupled client-daemon architecture.

TWS does not open its local TCP socket (ports 7497/7496) on localhost until after a human successfully completes interactive username/password entry and approves the mobile 2FA challenge.
$ python3 scripts/ibkr_tws_executor.py --status
➔ API connection failed: ConnectionRefusedError(61, "Connect call failed ('127.0.0.1', 7497)")
3. Native Desktop Java GUI vs. Browser Sub-Agents
RUNTIME SCOPE
Antigravity's sub-agents include web browser automation tools (controlling Chromium DOM trees, clicking HTML elements, filling web forms).

However, Trader Workstation is a compiled desktop Java application (/Contents/MacOS/JavaApplicationStub) running native Swing/AWT graphics directly on macOS WindowServer. There is no web DOM or browser context to inspect or manipulate.
$ ps aux | grep -i "trader workstation"
PID 7090: .../Trader Workstation.app/Contents/MacOS/JavaApplicationStub
4. Hardware-Backed Two-Factor Authentication (2FA)
IDENTITY AUTH
Even if automated typing into the username and password fields were permitted by macOS, Interactive Brokers mandates a cryptographic handshake approval via the IBKR Mobile Key app on the user's physical phone.

Because the private enclave key resides exclusively on your mobile phone, automated trade transmission cannot occur until you tap "Approve" on your mobile device.
